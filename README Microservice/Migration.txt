Mục tiêu:

Tôi muốn chuyển đổi backend hiện tại từ kiến trúc Monolithic sang Microservice sử dụng Spring Cloud.

ĐÂY LÀ YÊU CẦU QUAN TRỌNG NHẤT:

- TUYỆT ĐỐI KHÔNG được sửa bất kỳ file nào trong thư mục backend hiện tại.
- Backend hiện tại chỉ dùng làm nguồn tham khảo để đọc nghiệp vụ.
- Hãy tạo một thư mục hoàn toàn mới có tên:

backend-microservice

Toàn bộ source code microservice phải nằm trong thư mục này.

==================================================

MỤC TIÊU CHÍNH

Giữ nguyên 100% nghiệp vụ hiện tại.

Frontend hiện tại vẫn sẽ được sử dụng.

Frontend không cần hoặc chỉ cần sửa rất ít.

Frontend sẽ gọi API thông qua API Gateway thay vì gọi trực tiếp Backend Monolith.

Tất cả API hiện tại phải hoạt động giống như trước.

Không được làm mất bất kỳ chức năng nào.

==================================================

KIẾN TRÚC YÊU CẦU

Sử dụng:

- Java 17
- Spring Boot 3
- Spring Cloud
- Spring Cloud Gateway
- Netflix Eureka
- OpenFeign
- Kafka
- Spring Security
- Spring Data JPA
- Docker
- Docker Compose
- Redis (nếu phù hợp)

Không cần Kubernetes ở phiên bản đầu tiên.

==================================================

YÊU CẦU PHÂN TÍCH

Đầu tiên hãy đọc toàn bộ project Backend hiện tại.

Phân tích:

- Module
- Chức năng
- Nghiệp vụ
- Quan hệ Entity
- Controller
- Service
- Repository

Sau đó mới quyết định cách chia Microservice.

KHÔNG được chia ngẫu nhiên.

Chỉ chia khi hợp lý.

==================================================

YÊU CẦU CHIA SERVICE

Hãy tự phân tích và chia thành các service phù hợp.

Ví dụ có thể gồm:

- Gateway
- Eureka
- Auth Service
- User Service
- Product Service
- Category Service
- Inventory Service
- Order Service
- Promotion Service
- Notification Service

Nếu dự án hiện tại không cần thì không bắt buộc phải tạo.

==================================================

DATABASE

Hiện tại dự án chỉ có một Database.

Hãy chuyển sang Database Per Service.

Mỗi Service sở hữu Database riêng.

Ví dụ:

Auth DB

User DB

Product DB

Order DB

Inventory DB

....

Không Service nào được truy cập Database của Service khác.

Chỉ giao tiếp bằng:

- REST API (OpenFeign)

hoặc

- Kafka

==================================================

API

Đây là yêu cầu quan trọng.

Toàn bộ API hiện tại phải được giữ nguyên.

Giữ nguyên:

- URL
- Request
- Response
- HTTP Status
- Validation
- Exception

Nếu cần thay đổi nội bộ thì Gateway phải mapping lại để Frontend không cần sửa.

==================================================

BUSINESS

Không được thay đổi nghiệp vụ.

Không được viết lại logic.

Chỉ refactor sang Microservice.

Business Logic phải giống hoàn toàn Backend hiện tại.

==================================================

SERVICE COMMUNICATION

Service giao tiếp theo nguyên tắc:

Đồng bộ:
- OpenFeign

Bất đồng bộ:
- Kafka

Kafka chỉ sử dụng khi hợp lý.

Ví dụ:

- Gửi Email

- Notification

- Log

- Audit

- Event

Không lạm dụng Kafka.

==================================================

API GATEWAY

Frontend chỉ gọi:

Gateway

Gateway sẽ route đến đúng Service.

Không Frontend nào gọi trực tiếp Service.

==================================================

EUREKA

Toàn bộ Service phải đăng ký lên Eureka.

Gateway sử dụng Eureka để tìm Service.

Không hardcode URL Service.

==================================================

SECURITY

Giữ nguyên cơ chế Login hiện tại.

JWT phải tiếp tục hoạt động.

Nếu hợp lý hãy tách Authentication thành Auth Service.

==================================================

DOCKER

Mỗi Service phải có:

Dockerfile

Toàn bộ hệ thống phải chạy được bằng:

docker-compose.yml

YÊU CẦU KHI THỰC HIỆN

Không được tạo code mới một cách tùy tiện.

Ưu tiên tận dụng code hiện tại.

Mỗi lần tách một Service phải:

- Di chuyển Entity
- Di chuyển Repository
- Di chuyển Service
- Di chuyển Controller
- Kiểm tra Dependency
- Đảm bảo API vẫn hoạt động

Nếu có chỗ nào chưa rõ hãy phân tích trước rồi mới thực hiện.

Không được tự ý thay đổi nghiệp vụ.

Ưu tiên kiến trúc sạch, dễ mở rộng, đúng chuẩn Spring Cloud Microservice.
